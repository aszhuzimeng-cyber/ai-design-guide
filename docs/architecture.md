# 项目架构与部署边界

## 当前架构

```text
自然语言输入
    ↓
需求澄清与设计意图（目标用户 / 页面重点 / 核心感觉）
    ↓  用户确认
信息架构方案（首屏 / 内容顺序 / 浏览路径 / 模块）
    ↓  用户确认
视觉语法方案（色彩 / 字体 / 卡片 / 密度）
    ↓  用户确认
生成约束 → DeepSeek → 单文件 HTML → 布局与视觉规则校验 → 预览/导出
```

| 模块 | 主要代码 | 作用 |
| --- | --- | --- |
| 画布和状态 | `src/App.tsx`、`src/types.ts` | 展示决策树、记录用户选择与修改 |
| AI 编排 | `src/ai/projectAi.ts`、`src/ai/pipeline.ts` | 分阶段调用模型并组织结果 |
| 方案应用 | `src/ai/apply.ts` | 将 AI 候选写入项目状态，同时保留用户选择 |
| 设计参考 | `design-reference/runtime/`、`src/ai/designReference.ts` | 为信息组织和视觉判断提供检索依据 |
| 生成约束 | `src/ai/generation*.ts`、`src/pageLayoutArchitecture.ts` | 将已选方案转成页面结构与视觉规则 |
| HTML 处理 | `src/ai/html.ts` | 整理生成结果并补充布局规则 |
| 本地接口 | `vite.config.ts` | 代理 AI 请求；可选导出到 MasterGo |

## 为什么目前不做大规模重构

需求澄清、用户确认、方案组织、生成与预览的职责已经可辨，原型也能完成端到端流程。申报阶段更需要可复现的运行说明、展示材料和明确的功能边界。大规模重构会增加回归风险，对评审理解项目帮助有限。

## 后续优先改进

1. **正式部署**：将 `vite.config.ts` 中的本地 AI 代理迁到独立服务，提供鉴权、调用限额和密钥管理，再发布可公开试用的线上地址。
2. **降低主界面耦合**：`src/App.tsx` 同时承载画布、交互和流程状态；在功能稳定后，按阶段拆分视图与状态逻辑。
3. **方案质量评估**：用不同页面类型和真实用户任务持续评估信息架构差异、视觉推荐理由与最终页面一致性。
4. **项目保存**：目前依赖 `localStorage`；若面向多人协作，再引入账户与云端存储。
